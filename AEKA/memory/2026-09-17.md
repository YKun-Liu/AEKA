## S6 工程计算工具实现（用户选定方向：工程计算）
- 新增 `tools/engineering_calculator.py`（5 个子命令 + --json）：
  - `storage`：码率×86400÷8 → GB/路·天；×路数×天数×开销×冗余；附磁盘/RAID 估算
  - `bandwidth`：并发×码率×峰值系数；可选链路余量
  - `fiber`：发射−接收 ≥ 连接器+熔接+km×每km损耗+余量；输出剩余余量与判定
  - `ups`：视在功率=W÷pf×安全系数；电池 Ah = Wh÷(V×逆变效率×放电系数)
  - `rack`：总功率/电流/散热 BTU
- 实测校验（手算对账一致）：
  - 4 Mbps×200 路×90 天 = 43.2 GB/路·天 → 777,600 GB（×1.05 开销 = 816,480 GB ≈ 816 TB）
  - 200×4×1.3 = 1040 Mbps；加 20% 余量 → 1.25 Gbps
  - 光纤 0/−24 dBm、10 km、2 连接器、4 熔接 → 预算 24 dB、衰减 7.9 dB、余 16.1 dB ✅
  - UPS 5000 W / pf0.9 / 60 min / 192 V → 5,556 VA → 选型 ≥6.94 kVA；电池 ≈34 Ah
  - rack 8×15+2×150+3×450 = 1770 W → 8.05 A、6039 BTU/h、配电容 ≥2212 W

### 环境与操作经验（本机）<!-- project: path:E:\openclaw\workspace -->
- 技术栈：Python（标准库 urllib/json/re）+ PyMuPDF（pymupdf）+ Pillow（PIL）+ Windows 自带 OCR（Windows.Media.Ocr，无需安装）。
- **PowerShell 坑**：① 多行 `python -c "…"` 会被解析为 ScriptBlock 而报错（`Exec failed: run python inline script`）→ 一律落成 .py 文件执行；② `2>&1 | Select-Object` 等管道重定向会按 GBK 重编码导致 UTF-8 中文乱码 → 直接执行（不经管道）输出正常；③ 大图 OCR 前需缩放到宽 ≤1600px（引擎单图上限约 2600px）。
- 浏览器自动化：`profile=user` 附加用户 Chrome 需其开启远程调试（否则 DevToolsActivePort 找不到）；用 OpenClaw 自管浏览器档可完成抓取（无需用户手动复制 Cookie）。
- openstd 取图要件（备忘）：会话 `JSESSIONID` + 请求头 `Cache-Alive: chunked` + 全套浏览器头（UA/Referer/Accept-Language: zh-CN/Sec-Fetch-*）；302 后静态目录 nginx 有防盗链（缺头返回 200 空流）。
