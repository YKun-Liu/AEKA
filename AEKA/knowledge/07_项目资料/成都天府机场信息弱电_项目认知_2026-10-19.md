# 天府机场信息弱电工程 —— 项目级认知（A 阶段提炼）

> **来源**：`E:\天府机场` 各标段技术规范书总则（四/三/二/一标段）+ 术语与机制抽取。
> **可信度：C 级（项目资料）**。这是**单个项目的工程口径**，不是规范要求，也不是行业通则。
> 用于理解民航大型机场弱电工程的实务逻辑；**引用条款须回查规范原文**。

---

## 一、系统分层：三个"世界"

天府机场把弱电系统分成三层，理解这个分层是理解后续所有接口关系的前提：

```
内部系统（本项目建设的系统）
   ├─ 基础弱电类（桥架、综合管路、布线、UPS 配电、机房）
   ├─ 通信类（传输承载网、NGN、网络）
   ├─ 基础平台（云计算、数据中台、企业服务总线）
   ├─ 生产运行类（A-CDM、IIS 航班信息集成、资源分配、AODB）
   ├─ 旅客服务类（航显、广播、自助值机、智慧出行、呼叫中心）
   ├─ 行李相关（BHS、行李全程跟踪、自助托运）
   ├─ 空侧运行类（A-SMGCS、VDGS、FOD、鸟情、净空）
   ├─ 安全安防类（视频监控、门禁、报警、安检信息、安防集成）
   └─ 经营管理类（POS、商业租赁、能源、设备设施）

外部系统（非本项目建设，必须对接）
   民航局 / 地区管理局 / 空管 / 航空公司 / 中航信 /
   联检单位（海关、边检、检验检疫）/ 公安 / 航油 / 航食 /
   地服 / 货运 / 交管委 / 轨道交通 / 高铁 / 客运 / 环保 / 应急办
```

**工程含义**：外部系统的接口往往**不在承包商可控范围**，是项目风险高发区。规范只规定"应满足接口要求"，但实际能不能对接、由谁协调，取决于外部单位配合度。

## 二、运行管理模式："统一指挥 + 分区管理 + 专业运行支持"

这是天府机场（也是国内大型机场通行做法）的运行架构：

| 层级 | 机构 | 职责 |
|---|---|---|
| **统一指挥** | **AOCC**（机场运行管理大厅） | 全场最高运行指挥机构，统一管理全局性和关键性业务、应急事件；"对内统一指挥、对外统一接口" |
| **分区管理** | 航站区 / 飞行区 / 公共区（GTC）管理中心 | 各区域内的运行管理 |
| **专业运行支持** | 旅客服务中心(PSC)、安全管理室、IT 监控管理中心、市政监控中心 | 按业务或专业提供支持 |

**AOCC 五大定位**：信息交互中心、安全管控中心、运行枢纽中心、服务监控中心、应急指挥中心。

**对应系统**：信息集成系统（IIS）、协同决策（A-CDM）、协同运行可视化、电子地图、功能中心工程——这些系统本质都是**为 AOCC 提供态势和决策支撑**。

## 三、集成机制：IDD + 企业服务总线 + 技术总协调人

这是**规范里几乎没有、但工程上最关键**的一套机制：

### 1. 技术总协调人（数据治理）
- 负责全场信息弱电的技术管理、协调、监督及**数据治理**
- 各标段承包商必须服从其技术管理
- 制定机场运行系统集成相关标准

### 2. IDD（Interface Definition Document，接口定义文档）
- **各标段承包商之间必须签署 IDD**，明确接口数据规范
- **IDD 的制定必须以数据治理成果为依据**
- 由各系统承包商负责本项目端的接口开发
- 这意味着：**接口不是"自然形成"的，而是合同化的、要签字的技术文件**

### 3. 企业服务总线（ESB）
- 各系统通过**机场企业服务总线**实现数据交换、服务注册、服务调用
- **视频除外**（视频走独立通道/流媒体）
- 总线承包商负责数据标准规范、服务注册管理、接入适配器开发
- 各系统承包商须提供接口需求、数据项范本、服务调用需求

### 4. 集成测试中心
- 建设期及投产后用于各系统开发、测试、培训的环境
- **意味着系统联调不是现场直接做，而是先在集成测试中心验证**

**这三条对工程管理的启示**：弱电项目的成败很大程度取决于**接口管理**，而不是单系统功能。招标文件把 IDD、总线、总协调人写进合同，就是为了把接口责任显性化。

## 四、标段划分与系统归属（本项目的实际切法）

| 标段 | 定位 | 典型系统 |
|---|---|---|
| **一标段** | 信息集成核心 | 信息集成系统（IIS）等核心平台 |
| **二标段** | 基础设施与安防集成 | 机房集成、综合布线、桥架、UPS 配电、视频监控、门禁、安防智能集成、建筑设备监控、全景增强监视 |
| **三标段** | 业务系统（34 个编号） | IBMS、天网、云计算、网络安全、停车场、POS、施工管理、贵宾服务、行李跟踪… |
| **四标段** | 旅客服务与前端 | 航显、广播、网络、NGN、传输承载、自助值机、智能安检线、离港控制、时钟、人脸识别、电子地图 |

**跨标段重复出现的系统**（口径可能冲突，需特别注意）：

| 系统 | 出现标段 |
|---|---|
| 机房集成工程 | 二标段、三标段 |
| 桥架及综合管路 | 二标段、三标段 |
| 综合布线系统 | 二标段、三标段 |
| 视频监控（报警） | 二标段、三标段 |
| 门禁（巡更） | 二标段、三标段 |
| 航班显示系统 | 三标段、四标段 |

**工程含义**：同一系统分属两个标段时，**界面划分是最大的扯皮点**（谁供设备、谁布线、谁调试）。看这类文件必须找"工程界面"章节。

## 五、工程界面（实务中最容易出问题的地方）

从四标段总则提炼的界面逻辑：

| 界面 | 责任划分 |
|---|---|
| **与装修单位** | 装修单位负责精装区末端设备点位综合；弱电承包商提供设备属性信息并配合 |
| **与 UPS 配电标段** | **前端设备配电由二/三标段 UPS 配电系统提供**；本标段只提用电位置、功率、插座需求，并确认插座规格匹配 |
| **与土建总包** | 协调机房管理、工作面移交、设备送电及安装条件 |
| **与信息安全系统** | 开放 API、配置文件、系统日志；配合统一安全认证；允许安装探针/代理 |
| **与技术总协调人** | 服从技术管理，提供数据内容与治理建议 |

**这是最容易忽略的一条**：弱电承包商通常不负责前端配电，但**必须提前提出用电需求**——提晚了就会扯皮。

## 六、责任期与交付

| 项 | 期限 |
|---|---|
| **软件缺陷责任期** | 行业验收合格之日起 **60 个月**（5 年） |
| **硬件缺陷责任期** | 行业验收合格之日起 **24 个月**（2 年） |

> 软件责任期长于硬件，反映大型机场信息系统的特点：硬件质保 2 年，但软件要持续维护 5 年。

## 七、存储期限（本项目实际口径）

从各系统技术规范书抽取（已语义过滤）：

| 系统 | 存储期限 |
|---|---|
| NGN 信息交换 | 180 天 |
| 视频监控（报警） | 90 天 |
| 全景增强监视 | 90 天 |
| 天网系统 | 90 天 |
| 公共广播 | 90 天 |
| 自助行李托运 | 90 天 |
| 行李全程跟踪 | 60 天 |
| 停车场 | 30 天 |
| FOD | 15 天 |
| 商业 POS | 7 天 |

**认知要点**：**不能一律按 90 天算存储**。录像类（监控/天网/全景）确实 90 天，但业务类系统差异极大——POS 只有 7 天，NGN 长达 180 天。做存储容量计算前必须先确认系统类型。

## 九、对我（AEKA）的能力启示

1. **民航弱电 ≠ 安防 + 布线**：74 个子系统，涵盖业务、平台、空侧、经营，远超我原来的认知
2. **接口管理是核心能力**：IDD、ESB、总协调人——回答工程问题时，接口界面往往比单系统参数更重要
3. **存储/带宽等参数必须分系统**：不能用一个通用值套所有系统
4. **项目口径 vs 规范要求要分清**：本文件是 C 级认知，不能当 A 级规范引用
5. **标段划分导致同一系统多处出现**：遇到"视频监控"要问清是哪个标段的
